# ESPidi-rebuilt — дебаг и оптимизация прошивки ESPidi

## Что это
ESPidi — открытый MIDI-процессор на ESP32-C3 (автор — Евгений). Этот проект: дебаг
и оптимизация его прошивки. **Код — Евгения**; предлагать правки и улучшения,
не переписывать логику без согласования.

## База
Отправная точка — **последний рабочий вариант от Евгения (архив `ESPidi_2`)**,
а не публичный `EugeneCarlo/ESPidi`: публичный отстаёт («много поменял логики в
новом файле»). Публичный репозиторий держать как референс/историю.

## Платформа
- ESP32-C3: одно ядро RISC-V, BLE 5.0 (без Classic BT). Arduino framework (arduino-esp32).
- `Serial1` txBufferSize по умолчанию 0.
- EEPROM эмулируется через NVS; запись только при `_dirty` — т.е. простой PLAY во flash
  не пишет (исключение — ARP).
- MIDI (FortySevenEffects): `UseRunningStatus=false`, `Use1ByteParsing=true` по умолчанию.
- MIDI: 31250 бод, TRS Type A/B, MIDI Clock 24 PPQN, BLE-MIDI упаковка 8→7 бит.

## Главный вывод ревью
Настоящий фикс таймингов — **вынести CLOCK в высокоприоритетную задачу**,
а не отрисовку OLED. Выносить отрисовку в задачу не нужно (позиция Евгения, согласованная).

## Что НЕ баги (осознанные решения Евгения)
- **CC123** (All Notes Off) на всех каналах — задумано: обрываются все ноты на всех каналах.
- **Сохранение во flash по ходу** — при простом PLAY не происходит (EEPROM пишет только
  при `_dirty`).
- **«3-я ошибка»** — это недоделанная предзагрузка, а не баг.

## Реальные/открытые проблемы
См. Claude-док «ESPidi: найденные проблемы и варианты решения» (severity + статус для
версии 29.08): блокирующая отрисовка в тайминге, стоп SONG на 128 × NoteOff, баги
SEQUENCER (transpose / Tie / record), перекрытие EEPROM, двойная отправка STRUM.
В 29.08 переписан пул активных нот (чинит transpose/Tie), но введён CC123-на-всех-каналах.

## Уточнение по «сбросу нот при смене паттерна»
Имелось в виду: слать Note Off только для реально звучащих нот (≤ 6), а не все 128 —
не «вообще не гейтить ноты».

## Сборка
**Каноническая сборка — PlatformIO** (`platformio.ini` в корне, ветка `rebuilt`; платформа,
борда, версии библиотек и флаги пинятся в репо; `pio run` / `pio run -t upload`).
Arduino IDE — только запасной вариант для быстрой заливки. Плата ESP32-C3.
COM-порт устройства — USB Serial Device (не Serial-over-Bluetooth link).
Исходники для PlatformIO — в `src/` (если `.ino` не собирается из-за прототипов —
переименовать в `.cpp` + `#include <Arduino.h>`).
Версии библиотек пинить точно. В `ESPidi_2` нет BLE/NimBLE (только UART MIDI на Serial1);
библиотеки: MIDI Library, Adafruit SSD1306/GFX. Если BLE появится — NimBLE 2.x ломает API 1.x.
**Baseline достигнут** (платформа espressif32 6.13.0, чистая сборка кода Евгения: flash 28%, RAM 6%).
`pio` = `~/.platformio/penv/Scripts/pio.exe`; первая сборка ~12 мин (качает тулчейн).
Форк публичный: github.com/zemuro/ESPidi-rebuilt (по согласованию — Евгений за максимальную открытость; архив взят из публичных файлов Telegram-чата проекта). Это отменяет пункт «Приватность» ниже. `ARDUINO_USB_CDC_ON_BOOT` трогать только если
USB-`Serial` дебаг не заводится (MIDI идёт по `Serial1`).

## Порядок работ (не нарушать)
1. Ветка `import-espidi2`: коммит-снапшот архива Евгения как есть. Ветка `rebuilt` — от неё.
2. `platformio.ini` → **чистая сборка немодифицированного кода Евгения = baseline**.
   Пока оригинал не собрался — НИЧЕГО не чинить.
3. Затем правки: первым делом CLOCK → высокоприоритетная FreeRTOS-задача (отрисовку не трогать).
4. Признанные Евгением фиксы — отдельными коммитами → PR в upstream.
