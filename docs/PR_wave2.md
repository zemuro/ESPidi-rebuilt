## Тайминг: ровный Clock при любой нагрузке + твои решения по поведению

Это вторая часть, про тайминг, плюс всё, о чём мы договорились по вопросам из первого PR. PR сделан поверх #1, поэтому в нём видны и коммиты первой волны. Смотреть стоит коммиты после `ui: rename STRUM to THRU`, их 13. Если сначала вольёшь #1, здесь останутся только они.

### Тайминг

Цифры — наибольший интервал между байтами Clock на выходе, 120 BPM (норма 20,8 мс):

| Что происходит | Было | Стало |
|---|---|---|
| Стык паттернов в песне | 146,6 мс | 21,7 мс |
| Отпускание аккорда в ARP | 139,1 мс | 21,7 мс |
| Шаги секвенсора | 37,2 мс | 21,4 мс |
| Смена PTRN во время игры | 37,2 мс | 23,5 мс |
| Вращение энкодера | 34,7 мс | 23,4 мс |

Что для этого сделано, по коммитам:

- **Гасим только свои ноты.** Песня на стыке паттернов и ARP при отпускании аккорда слали 128 NoteOff и CC 123, на что уходило около 120 мс; всё это время такты стояли. Теперь гасятся только реально звучащие ноты, это доли миллисекунды. Заодно перестали обрываться ноты других инструментов в цепочке.
- **Без CC 123 на каждом шаге секвенсора.** Это было примерно 15 мс на проводе на каждый шаг. Теперь свои ноты гасятся по одной, а CC 123 ESPidi больше не шлёт вообще.
- **Во флеш не пишем, пока играет.** Автосохранение настроек срабатывает в момент STOP, а не посреди игры.
- **Экран: отправляются только изменившиеся строки.** Обычно меняется одна строка из четырёх, а не весь кадр. Шина осталась на 400 кГц, Adafruit не трогали. Руслан смотрел на живом экране: артефактов нет.
- **Такты в отдельной задаче.** Это и есть «вынести CLOCK в высокоприоритетную задачу» из ревью. Новый файл `engine.cpp`: задача FreeRTOS с высоким приоритетом читает MIDI-вход, выдаёт такты и отправляет MIDI. Она просыпается каждые 0,5 мс и, отдельным таймером, точно к моменту каждого такта. Основной цикл занимается кнопками, экраном и файлами, общее состояние защищено мьютексом. Экран и чтение паттернов из LittleFS больше не задерживают такты.
- **Очередь отправки MIDI** (`midi_serial.cpp`). Clock, Start и Stop идут вне общей очереди и не ждут, пока уйдёт пачка нот.
- **Песня готовит следующий паттерн заранее.** Он читается из файла, пока играет текущий, поэтому на стыке ничего не загружается.
- **Первая нота после PLAY/Start** звучит на первой же доле, а не через шестнадцатую.

Подробный отчёт с графиками: [ESPidi_timing_report.pdf](https://github.com/zemuro/ESPidi-rebuilt/blob/wave2/docs/timing/ESPidi_timing_report.pdf).

### Сделано, как ты решил

- **Смена паттерна во время игры — параметр SWAP** (правая колонка секвенсора, под SAVE): **NOW** — шаг нового паттерна звучит сразу, следующий по сетке; **NEXT** (по умолчанию) — со следующего шага; **END** — после конца текущего паттерна, новый с начала. Позиция в новом паттерне считается по шагам с PLAY по модулю его длины, поэтому паттерны разной длины больше не конфликтуют. Попутно ушёл сдвиг сетки: раньше шаг, на котором переключили, растягивался, и секвенсор сползал с Clock. SWAP хранится в настройках (EEPROM, один байт в конце блока); после обновления там будет NEXT.
- **TAP** — среднее последних трёх интервалов. Расчёт теперь в одном месте (`clock_tap()`), а не в трёх одинаковых копиях.
- **Pitch Bend, Program Change, Aftertouch, SysEx и системные сообщения** проходят на выход ровно тогда, когда проходят ноты: ARP — остановлен или THRU = ON; SEQ — THRU = ON; SONG и SETTINGS — всегда; MONITOR — никогда.
- **Несохранённые правки** — вариант «б»: первый поворот PTRN (или SONG) номер не меняет, SAVE мигает около двух секунд; повторный поворот, пока мигает, переключает без сохранения. Щелчки одного быстрого поворота считаются одной попыткой, так что выбросить правки случайно нельзя.
- **GATE — свойство паттерна** (вариант «г»): секвенсор берёт GATE из файла паттерна, а песня играет ноты по GATE своего паттерна, с записанными длинами нот и Tie — раньше в песне всё было легато. Учти: смена PTRN теперь меняет и GATE, а правка GATE помечает паттерн несохранённым.
- **Песня в REV** стартует с последнего шага, как секвенсор: D C B A вместо A D C B.

### Чего не трогал

- SWING и RAND/PROB паттерна в песне по-прежнему не применяются: договаривались только про GATE. Если нужно — скажи.
- Частоту I²C не поднимал: кадр теперь уходит на экран в фоне и на такты не влияет, а выше 400 кГц SSD1306 работает уже за пределами своей спецификации.

### Как проверяли

Тот же стенд, что и в первый раз: компьютер играет ноты, шлёт Clock, нажимает кнопки через USB-консоль тестовой сборки и смотрит, что выходит из MIDI OUT. Тестовая обвязка в этот PR не входит; она живёт в форке ([zemuro/ESPidi-rebuilt](https://github.com/zemuro/ESPidi-rebuilt), папка `tools/`, окружение `pio run -e test`).

Мануал обновлён под все изменения, с настоящими снимками экрана: [ESPidi_manual.pdf](https://github.com/zemuro/ESPidi-rebuilt/blob/wave2/docs/manual/ESPidi_manual.pdf).

### Как попробовать

В Arduino IDE: на странице ветки `pr/wave2` нажми Code → Download ZIP и открой `Firmware/ESPidi/ESPidi.ino` как обычно. Новые файлы `engine.cpp`, `engine.h` и `midi_serial.cpp` лежат рядом и подхватятся сами. Прошивка выросла на несколько килобайт.
