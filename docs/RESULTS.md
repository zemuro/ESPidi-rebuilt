# Результаты автотестов на железе — 2026-10-02

Прошивка: `ESPidi_2` (код Евгения без изменений логики) + тестовая обвязка `env:test`.
Стенд: ESP32-C3 Super Mini, TRS MIDI (Type B), USB-MIDI кабель `USB2.0-MIDI`, Windows 11.
Полный отчёт с метриками: `tools/results/latest/summary.md` (генерируется прогоном, в git не входит).

Итог: **23 дефекта подтверждено**, 7 расхождений — вопросы к автору («задумано ли так?»),
остальные гипотезы не воспроизвелись (сохранение паттернов, точность темпа, транспорт, поток CC и др.).

## Подтверждённые дефекты

### Тайминг (главный вывод ревью)
Внутренний Clock при 120 BPM: номинал 20,83 мс между тиками, допуск 3 мс опоздания.

| ID | Что | Измерено |
|---|---|---|
| B5 | Стык паттернов в SONG: `stopAllNotes` = 128 × NoteOff + CC123 | блокировка **117 мс**, разрыв Clock **146 мс** |
| B6 | Отпускание последней клавиши в ARP: `stopSounding` = 128 × NoteOff | блокировка **118 мс**, разрыв Clock **139 мс** |
| B7 | Смена PTRN во время игры: чтение LittleFS в основном цикле | `mel.load` 13 мс, опоздание тика 16 мс |
| B3 | Перерисовка OLED на каждый щелчок энкодера | `ui.draw` ≈ 14 мс, опоздание тика 13,8 мс |
| B4 | SEQ: интервалы Clock «плавают» 4–37 мс (σ 9,3 мс) на каждом шаге | 96 выбросов за 12 с |
| B8 | Автосохранение EEPROM в основном цикле | опоздание тика 3,7–10,9 мс |
| B13 | Пропал внешний Clock — звучащая нота не гаснет | зависшая нота |

### MIDI
| ID | Что |
|---|---|
| **C11** | **Один SysEx на входе отключает приём нот/CC до перезагрузки** (Clock при этом проходит). Причина (библиотека MIDI / прошивка / как кабель передаёт SysEx) ещё не найдена — нужен лог сырых байтов. Критично: SysEx шлют многие устройства. |
| C1 | SEQ, STRUM=ON без записи: каждая нота уходит на выход **дважды** (2 NoteOn / 2 NoteOff) |
| C2 | ARP, HOLD=ON, остановлен: NoteOff съедается → зависшая нота |
| C3 | ARP: новая клавиша → NoteOn поверх звучащей ноты без NoteOff |
| C10 | SEQ, REC + STRUM=OFF: NoteOn проходит на выход, NoteOff съедается → зависшая нота |
| C6 | MONITOR показывает канал на 1 больше (CH1 → «CH2» … CH8 → «CH9»), проверено по пикселям экрана |

### Секвенсор и песня
| ID | Что |
|---|---|
| D1 | Запись под Clock попадает в шаг **N+1** (нота, сыгранная на звучащем шаге 0, легла в шаг 1) |
| D3 | Цепочка из 2 Tie: нота 18 тиков вместо 15 (один Tie — верно, 9 тиков) |
| D4 | PEND: после уменьшения LENGTH до 4 playhead остаётся на шаге 9 |
| D8 | CLEAR сбрасывает внутренний номер слота в 0 при PTRN 5 на экране → после перезагрузки грузится не тот паттерн |
| D10 | SONG, RND + CYCLE OFF: песня останавливается в случайный момент (сыграно 1–4 шага из 8) |
| D11 | SONG: заглушённый шаг длится 96 тиков вместо 48 (pauseLength × DIV вместо длины паттерна) |

### Хранение настроек
| ID | Что |
|---|---|
| E1 | **Перекрытие EEPROM**: после перезагрузки SEQ SWING = номер паттерна, RAND = BPM, PROB = канал песни. При BPM > 127 весь блок SEQ (MODE, CH, GATE…) сбрасывается в умолчания |
| E3 | Выбранное в меню приложение не запоминается |
| E4 | ARP после перезагрузки стартует в состоянии PLAY |

## Вопросы к автору (поведение, возможно задуманное)
| ID | Наблюдение |
|---|---|
| B12 | TAP-темп считается по последнему интервалу, без усреднения (600/600/600/800 мс → 69–70 BPM вместо ≈ 92) |
| B14 | После Start первая нота SEQ звучит на 6-м тике (на шестнадцатую позже доли) |
| C4 | CC123 на 16 каналов на **каждом** шаге воспроизведения, а не только на STOP (80 сообщений за 5 шагов) |
| C5 | Pitch Bend, Program Change, Aftertouch (оба), SysEx не проходят насквозь |
| D7 | Несохранённые правки молча теряются при смене PTRN |
| D12 | SONG игнорирует GATE паттерна (нота 6 тиков против 1 в SEQ при GATE=20) |
| D15 | SONG в REV стартует с шага 1 (SEQ в REV — с последнего) |

## Не воспроизвелось (работает как ожидалось)
B1/B2 (простой и ARP — без опозданий*), B11 (темп точен: отклонение 0,005 %), C7, C9 (8 клавиш × 4 октавы = 32 ноты),
D3 (один Tie), D5 (лимиты записи 6 нот / 3 CC), D6 (файл паттерна побайтово сохраняется), E5 (простой PLAY не меняет EEPROM —
заявление Евгения подтверждено), G1–G4 (внешний Clock, транспорт, проброс), H1 (5000 CC при внешнем Clock — без потерь), H4.

\* B2 проходит потому, что перерисовка запускается сразу после тика шага и успевает до следующего тика (14 мс < 20,8 мс);
при перерисовке «не в фазе» (B3) опоздание 13,8 мс.

## Особенности стенда, выявленные по ходу
* Ableton Live держит порты `USB2.0-MIDI` и при зависании блокирует Windows MIDI Service (`midisrv`) — на время тестов закрыть.
* USB-CDC ESP32-C3 теряет первый обмен после сброса и короткие ответы без `flush` — учтено в обвязке.
* Один из двух переходников TRS→DIN не работал на выходе ESPidi (на входе — работает).
