# ESPidi — план тестов для подтверждения багов

Прошивка: `ESPidi_2` (baseline `d805b27`, сборка PlatformIO `9f0779f`). Плата: ESP32-C3 Super Mini.
Цель — **подтвердить или опровергнуть** на железе гипотезы, полученные чтением кода, **до** любых правок.
Колонка «Гипотеза» — что предсказывает код; «Ожидание» — как должно быть у исправной прошивки.
Все номера строк относятся к `Firmware/ESPidi/`.

Статусы: ☐ не проверено · ✔ баг подтверждён · ✘ не подтверждён · ≈ поведение by design (занести в мануал).

> **Автоматизация:** большая часть тестов реализована в [`tools/`](../tools/README.md) (pytest + тестовая прошивка с USB-консолью). Список автоматизированных ID и то, что остаётся ручным, — в `tools/README.md`.

## 0. Оснастка

| Что | Зачем |
|---|---|
| USB-MIDI интерфейс (или второй MIDI-девайс/DAW) на MIDI OUT ESPidi | Видеть, что ESPidi реально отправляет |
| MIDI-клавиатура или DAW на MIDI IN ESPidi | Источник нот/CC/Clock |
| Монитор MIDI на ПК (MIDI-OX / Midi Monitor / `mido`) с **метками времени** | Интервалы Clock, дубли, зависшие ноты |
| Логический анализатор на GPIO10 (MIDI TX), опционально | Точный джиттер в мкс; ПК-метки на Windows дают ~1–2 мс, этого хватает для событий ≥ 5 мс |
| Serial-отладка по USB (`pio device monitor`) | Временные `Serial.println` для замера времени цикла (только в отдельной ветке, не в baseline) |

Арифметика, на которую опираются гипотезы: MIDI 31250 бод = **0,32 мс на байт**. 128×NoteOff по 3 байта = 384 Б ≈ **123 мс**; CC123 ×16 каналов = 48 Б ≈ **15 мс**. Один 24-PPQN тик при 120 BPM = **20,8 мс**. Полный кадр OLED 128×32 по I²C 400 кГц ≈ **11–12 мс**. `Serial1` без TX-буфера (`txBufferSize=0`) → `write` блокирует цикл.

Приоритет: **P0** — главные подозрения (тайминг, потеря данных); **P1** — ошибки логики; **P2** — UX/косметика/робастность.

## B. Тайминг (главный вывод ревью — вынос CLOCK в задачу)

Общая методика: SETTINGS → **CLKOUT ON**, CLKIN OFF, BPM 120. На ПК пишем метки времени байтов `0xF8`. Идеал: интервал 20 833 мкс. Считаем min / max / σ и **число интервалов > 25 мс**.

## E. Хранение настроек (EEPROM/NVS)

Адреса из `config.h` и жёстко заданные в `saveAllSettings` расходятся. Размеры: `ArpParams`=11 Б, `MelSeqParams`=12 Б, `SongParams`=6 Б. Сохранение: ARP@4..14, SEQ-params@15..26, **номер паттерна@24**, **SONG-params@25..30**, номер песни@31, SETTINGS@32..36.
Т.е. номер паттерна лежит на байте `swing` (смещение 9 в SEQ), а `bpm`/`channel` песни — на байтах `randomness`/`probability`.
